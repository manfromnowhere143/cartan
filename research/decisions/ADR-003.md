# ADR 003: preserve interface semantics and make the research legible

16 November 2026. Owner: research. Adopted before this block's implementation.
The operator explicitly authorizes the root README and continued engine work.
Research owns those changes in this worktree; UI and setup retain their existing
areas. Cloud access is available by operator instruction, but this bounded task
needs no cloud service, paid job, deployment or new model session.

## Evidence and correction

The public G1 interface document in [S17](../block-2/sources.md) distinguishes
mechanical engagement, electrical contact and controller power. It also separates
command acknowledgements from sensor telemetry. The first generic exchange model
compresses module separation and connector separation into one field; it cannot
represent all those phases. Preserve its restricted results, but do not reuse
that state encoding as a faithful vendor-interface model. No current firmware,
fault envelope or calibrated telemetry mapping has been recovered.

## Decision

Add a small **logical interface evaluator** in `backend/interface_evidence/`.
Keep mechanical retention, transfer support, electrical contact, controller power,
source isolation and residual-voltage condition as independent propositions.
Enumerate a bounded logical world set and assess a declared command precondition
over every retained world. Return admissible/refuted/unresolved/inconsistent with
supporting or contradicting witnesses. Those are conclusions within the logical
contract, never physical authorization or proof of mechanism reachability.

Input reports retain identity, time, epoch, status, unit and evidence mode. The
public preliminary profile provides report vocabulary, not a physical calibration.
Receipt/processed ACKs never constrain physical propositions. Default report
interpretation records observations without inferring retention or isolation.
An explicitly synthetic, assumed fault-free binding may constrain constructed
worlds for verification. No hidden transition from that assumption to a physical
test or validated mapping is allowed. Source power and controller power remain
distinct even when both are colloquially called “power.”

This is a semantic/decision analysis extension, not a third physics simulator or
an unearned autonomous controller. Alternatives rejected for this block: a new
contact dynamics model without geometry; copying preliminary packet layouts into
a hardware driver; learning a telemetry mapping without real data; importing
Nisayon's implementation or evidence. The programs remain separate.

New research artifacts use `cartan-interface-analysis/1.0.0`. Frozen v1, prior
models and evidence remain unchanged. UI integration needs its own reviewed
adapter. New records will be available through a committed checkpoint only.

## Bounded verification plan

Freeze the [logical specification and cases](../block-3/protocol.md) before
execution. One worker, at most 64 worlds per case, 32 reports, 100 cases, five CPU
seconds and the same recorded 256 MiB address-space request where supported.
Keep complete reports, interpretation reasons, remaining worlds and witnesses.
Cross-check the optimized decision against a separately written explicit reference.
Preserve negative and inconsistent cases. A clean contradiction is not “safe.”
No workload, safety rate, recovery time or cost advantage follows from this study.

## README and diagram decision

Replace the setup-only front page with a stable scientific introduction, concrete
interrupted-exchange question, implemented architecture, evidence table, limits,
reproduction commands and next experiment. Setup details remain linked through
the handoff and coordination records. Do not carry forward stale launcher claims.
Nisayon's opening, architecture and evidence sections were read as an editorial
benchmark only; none of its results, code, wording or product status transfers.

Use three small Mermaid diagrams with distinct jobs: physical facts that must not
be collapsed; implemented information flow; and the research-to-physical evidence
gates. Each gets an accessible title/description, explicit modeled/proposed labels,
short text and redundant status cues beyond color. Render and inspect all diagrams.
Use standard flowchart syntax compatible with the installed Mermaid CLI 11.4.2;
newer beta syntax is unnecessary. Rendering uses one existing local headless
browser at a time, no installs or security-disabling flags, with a 60-second
process timeout and retained resource observations. Backend runs remain separate.

The review criteria are clarity, accuracy, readable diagrams and reproducibility,
not claims of outperforming a university or company. This presentation remains a
research concept with no invented customer, flight heritage or measured superiority.
