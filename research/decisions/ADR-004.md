# ADR 004: model the observation path before the recovery policy

16 November 2026. Research owns this block. Identity and clean working state were
verified at `73030a9`. Setup and UI remain separate worktrees at `70456b0` and
`de81efb`; neither is edited or controlled here. The operator requested continued
physical observation-model work and preparation for GitHub publication. License
and visibility choices are pending; research can proceed independently.

The [source review](../block-4/sources.md) recovered a later public HOTDOCK design
document, mechanism-indication guidance and current metrology material. This
supports a documented observation-path model. It does not provide a complete
current interface, hardware calibration or fault coverage. Earlier generic models
and their evidence stay frozen.

Adopt three separate representations. The interface dossier records physical
quantities, sensor location, causal dependencies and missing qualification. A
bounded numerical observer computes an interval for voltage at a named terminal
pair and query time, conditional on explicit gain, bias, error and rate bounds.
A separate topology check asks whether all declared sources are disconnected
from a target under the declared possible edge states. Neither result supplies
physical authorization. Mechanical retention remains an obligation involving
engagement and load capacity; no invented cam profile or encoder threshold is used.

Prefer exact rational arithmetic and small, inspectable algorithms. Do not fit a
learned model without traces, infer a hard bound from a coverage percentage,
decode an inconsistent historical packet table, or build a contact simulator
without geometry. Graph cuts and interval inversion are established techniques,
not claimed algorithmic contributions. A competent baseline using the same
equations and information must receive the same conclusion.

Implement only under `backend/observation_model/`, with independent configuration,
tests and retained results. Outputs use `cartan-observation-analysis/1.0.0` and
remain constructed fixtures. Frozen v1 and prior models are unchanged. A UI adapter
requires a separate reviewed contract; no driver, server or actuator is added.

The [specification and protocol](../block-4/specification.md) precede code. Freeze
cases before execution. Use one worker, five CPU seconds per study invocation,
at most 256 topology assignments, 32 nodes and 16 edges, fewer than 100 cases,
and output below 10 MiB. Request the prior 256 MiB process cap and record OS
support. Source downloads are bounded to 25 MiB and processed sequentially;
11 MiB of PDF sources sufficed. No cloud job or new dependency is justified.

Falsify the implementation with reverse polarity, near-threshold uncertainty,
clock uncertainty, wrong measurement point, stale data, zero gain, missing bounds,
probabilistic coverage, possible sensor failure, incomplete source inventory,
backfeed and disagreement with an independently written reachability reference.
Any unexpected disagreement stops the study and is retained. A successful check
establishes only the declared software behavior. Continue physical work only when
the dossier's calibration, coverage and owner-limit obligations are met.

The publication preparation will audit contents and rights, keep source documents
outside the release, and bind the README to retained results. The operator's prose
preference removes decorative emphasis and separators; diagrams retain necessary
syntax. Do not infer a license grant or public visibility from the request to
prepare the release. Those choices have been asked explicitly.
