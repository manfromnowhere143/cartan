# ADR 002: check recovery evidence before optimizing recovery

Date: 16 November 2026. Owner: research. Adopted for the next bounded software
block before implementation/execution. Source: [new primary review](../block-2/sources.md).
The operator authorizes continued autonomous research and bounded build work.
Ambition is not evidence of superiority or permission for unbounded spending.

## Decision and scope

Build a small, independently checkable analysis of evidence needed for a recovery
decision. Compare a competent conventional counting rule with a possible-state
observer under **identical** information and fault assumptions. Preserve a null
result if they match. Separate measurement value from algorithm value. Add exact
interval counterexamples and a bounded residual-voltage calculation to test what
a numerical certificate actually means. Do not install a learned planner, GPU
stack, contact simulator or flight middleware without the corresponding problem
and data. Recent active diagnosis work makes that broad topic established prior art.

This block covers one retention fact and one electrical envelope, not a complete
exchange controller. A true retention fact alone cannot authorize release: support,
contact, load, circuit and time constraints are separate required facts. Sensor
fault bounds are exploratory assumptions, not recovered HOTDOCK specifications.

| Alternative | Decision |
|---|---|
| Claim a new uncertainty controller from the first model | Reject: a false report can remove truth; no comparative gain exists |
| Large probabilistic/learned model | Defer: no calibrated fault likelihoods or real observations |
| Implement 2026 differentiable diagnosis wholesale | Defer: physical dynamics and disturbance bounds are missing; an optimizer cannot validate those assumptions |
| Exact finite observer and competent B0 | Adopt as a transparent comparison with a mathematical lower bound |
| Better sensing/passive interlock | Retain as an explicit system alternative, with unknown physical burden |
| General diagnosability/model-checking framework | Defer; demonstrate the smallest useful bounded instance first |

## Architecture and boundaries

New code lives in `backend/certificates/`; block-1 code, evidence and contract v1
remain frozen. Input is versioned assumptions plus dated, identified observations.
An ingestion gate rejects stale/old-epoch evidence and duplicate acquisitions.
B0 counts contradictory reports; C propagates possible truth/error-count states.
Neither reads truth. An independent harness enumerates allowed histories and
compares each issued fact against the generating truth. The output is a retention
fact (`locked`, `not_locked`, `unresolved`, `inconsistent`) and proof assumptions,
never an actuator command. An inconsistent belief never means permission.

Rational arithmetic checks closed interval intersections and bounds exponential
decay. No floating-point tolerance may turn touching sets into disjoint sets.
Numerical optimization may eventually propose actions, but a separately checked
inclusion/separation certificate must justify them. This is an engineering rule,
not a claim of novel mathematics or formally verified software.

Evidence exports use `cartan-certificate-study/1.0.0` as a research artifact. They
are not v1 `Run` records or physical measurements. UI must not auto-adapt them.
A future reviewed adapter will preserve model assumptions, unresolved states,
counterexamples and evidence scope. Keep `contracts/cartan/v1/` byte-identical.

## Bounded protocol and architecture priorities

1. Close public-source gaps and identify incompatible interface semantics.
2. Prove and test conditional observer soundness and necessary observation counts.
3. Compare B0/C on all declared finite traces; include B2, common-cause failure,
   duplicate data, missing data and no-diagnosis cases without inventing human tests.
4. Derive an electrical waiting envelope with parameter uncertainty and backfeed;
   state exactly when passive waiting cannot certify the chosen condition.
5. Only then seek a documented real interface envelope for comparative recovery.

One worker, no installs/services/GPU. At most 100 primary histories per invocation,
32 observations per history, 5 CPU seconds, requested 256 MiB address space where
supported; the previous macOS refusal remains an expected platform limitation.
Small analytic/unit checks are counted separately, bounded by the frozen protocol.
Retained JSON target below 10 MiB; reading scratch below 250 MiB. Stop and retain
failure if caps or soundness checks fail. No stress testing of memory enforcement.

Freeze [mathematics](../block-2/mathematics.md) and [protocol](../block-2/protocol.md)
before execution. Exhaustive means only the declared finite model, not all faults
or all spacecraft. B1 human performance, full recovery, qualification, costs and
mission superiority remain unmeasured. If B0 matches C, report it and stop claiming
an algorithmic edge; pursue measurement assurance only if the actual task warrants it.
